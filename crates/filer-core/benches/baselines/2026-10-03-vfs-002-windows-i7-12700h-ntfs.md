# Batched Local Enumeration on Windows, 2026-10-03

A 256-row metadata first page of a 10,000-entry NTFS directory took 5.71 ms, while the fast first page took 2.47 ms. The metadata page sent every `DirEntry::metadata` call through `tokio::fs`, one blocking-pool hop per row. This record measures VFS-002, which reads each page and its metadata inside one blocking task, on one Windows machine. It also tests whether a native Win32 enumeration beats `std::fs::ReadDir` inside that task.

## Machine Profile

- OS: Windows 11 IoT Enterprise LTSC, build 26100, x86_64
- CPU: Intel Core i7-12700H, 14 cores, 20 logical CPUs, on AC power
- Disk: WD PC SN810 NVMe SSD, NTFS volume
- Rust: rustc 1.99.0, target `x86_64-pc-windows-gnu`
- Cargo: 1.99.0
- Before revision: `355e913`, per-entry `tokio::fs` enumeration
- After revision: `9989c25`, `std::fs::ReadDir` in one blocking task per page or batch
- Native comparison base: `da9fcb4`

The runs generated 10,000 empty `.dat` files in an isolated Git worktree and used a 256-entry page and 3 warmups. Each revision was built in its own `CARGO_TARGET_DIR`, because worktrees sharing one target directory reused the first worktree's `filer-core` build.

```bash
FILER_BENCH_FIXTURE_ROOT=D:/Project/Filer/target/bench-fixtures cargo bench -q --target x86_64-pc-windows-gnu -p filer-core --bench large_directory
```

The machine ran a desktop session with a browser and a music player at about 24% CPU load when sampled. Medians for the same binary moved by up to 65% between rounds, so each comparison below alternates revisions within a round and compares only inside a round.

## Before and After

Each revision ran twice with 20 timed samples, alternating before and after. The table shows the first run of each. Each second run matched its first run's metadata first-page median within 0.17 ms.

| --- | --- | ---: | ---: | ---: | ---: |
| Metadata first page | before | 5.705 | 6.027 | 2,937 | 724,341 |
| Metadata first page | after | 2.064 | 2.769 | 2,126 | 455,898 |
| Fast first page | before | 2.466 | 2.642 | 2,423 | 640,048 |
| Fast first page | after | 2.075 | 2.405 | 2,127 | 456,298 |
| Fast next page | before | 0.916 | 0.963 | 2,374 | 444,700 |
| Fast next page | after | 0.625 | 0.750 | 2,111 | 281,302 |
| Sorted first page | before | 40.685 | 42.674 | 90,478 | 25,875,320 |
| Sorted first page | after | 29.486 | 31.400 | 80,204 | 19,493,862 |
| Full snapshot | before | 35.677 | 36.637 | 90,374 | 14,990,493 |
| Full snapshot | after | 22.217 | 23.449 | 80,060 | 8,548,237 |

The metadata first page is 2.8 times faster and lands within 0.02 ms of the fast page. On Windows, `std` enumerates with `FindFirstFileExW` and `FindExInfoBasic`, and `DirEntry::metadata` copies size, timestamps, and attributes from the enumeration record without a syscall. The 3.24 ms the metadata page used to cost over the fast page was therefore all pool hops, about 12.6 µs for each of the 257 rows a page reads. The page also allocates 268 KB less.

## Native Enumeration

Two measurements compared `std::fs::ReadDir` with Win32 enumeration that builds rows straight from the find record, which skips the per-entry `DirEntry` that `std` creates by cloning a shared root path and copying the 592-byte find record.

A standalone program read the same 10,000-entry directory on one thread and built a path, a name, size, three timestamps, and attributes for each row. It ran three times with 20 warmups and 200 samples per variant, interleaved.

| Variant | 257-row page median ms | 10,000-row read median ms |
| --- | ---: | ---: |
| `std::fs::ReadDir` | 1.47 to 1.62 | 11.82 to 12.48 |
| `FindFirstFileExW`, `FindExInfoBasic` | 1.40 to 1.56 | 10.39 to 10.95 |
| `FindFirstFileExW`, `FIND_FIRST_EX_LARGE_FETCH` | 2.69 to 2.89 | 11.88 to 12.74 |
| `GetFileInformationByHandleEx`, `FileFullDirectoryInfo`, 64 KB buffer | 2.68 to 2.86 | 11.48 to 12.40 |

The large-buffer variants fill a larger buffer before they return the first row, so they add 1.2 ms to a first page. On a full read, `FIND_FIRST_EX_LARGE_FETCH` is slower than `std`, and the handle variant saves 0.1 to 0.4 ms. `FindExInfoBasic` without flags, which is the call `std` already makes, wins on both reads: about 0.07 ms per page and 1.5 ms per full read. A 257-row page costs 1.47 ms although 10,000 rows cost 11.8 ms, so opening the enumeration takes about 1.2 ms of every first page, and no variant reduces it.

A throwaway prototype then replaced `std::fs::ReadDir` in `vfs/local_listing.rs` with the `FindExInfoBasic` variant. Four rounds alternated a `9989c25` control, the `da9fcb4` base, and the prototype, each with 60 samples.

| Round | Metadata first page, base ms | Metadata first page, native ms | Full snapshot, base ms | Full snapshot, native ms |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 2.940 | 2.702 | 36.364 | 32.332 |
| 2 | 2.898 | 3.043 | 34.558 | 33.951 |
| 3 | 2.136 | 2.080 | 21.848 | 24.007 |
| 4 | 2.151 | 2.093 | 21.634 | 20.860 |

In the two quiet rounds, 3 and 4, the native metadata page saved 0.06 ms, about 3%. The control binary moved by 0.28 ms between those same rounds, and the full-snapshot difference changed sign between rounds. The gain is smaller than run-to-run variation on this machine.

## Decision

VFS-002 keeps `std::fs::ReadDir` on Windows and adds no `windows-sys` dependency. The native path would add unsafe FFI and a second implementation of row kind, timestamp, and symlink or junction classification for a 0.06 ms first-page gain that the end-to-end benchmark cannot separate from noise. The 1.2 ms enumeration open is the larger Windows first-page cost, and none of the tested APIs reduces it.
