# Large Directory Baseline, 2026-09-04

This baseline measures commit `6d3e07c` through the public `Command::Scan`,
`Event::DirectoryPageLoaded`, `Command::Extension`, and
`Event::FileDecorationsUpdated` contracts after PIPELINE-003 landed.

## Machine Profile

- OS: Linux 6.12.101+deb13-amd64, x86_64
- CPU: Intel Core i7-11800H, 16 logical CPUs
- Rust: rustc 1.97.1 (LLVM 22.1.6)
- Cargo: 1.97.1
- Filesystem: Btrfs on NVMe, compression zstd level 1
- Fixture: 10,000 empty files in a directory inside an isolated Git worktree
- Page size: 256
- Sampling: 3 warmups, 20 timed samples per scenario

The command used a fixture root on Btrfs instead of the system temporary
filesystem:

```bash
FILER_BENCH_FIXTURE_ROOT=target/bench-fixtures cargo bench -p filer-core --bench large_directory
```

Fixture generation took 83.094 ms and was excluded from every timed sample.
The decoration scenario starts timing after the Git status backend accepts its
request. It waits for `FileDecorationsUpdated` after the listing sample ends, so
Git completion time is not included in listing latency.

## Gate Status

The public structural paging test passes. Its controllable stream yielded the
required 257 rows, one page plus one lookahead, did not reach the directory end,
and emitted the first 256-row page with a continuation cursor.

The decoration ordering test passes with the backend held open: the first
directory page arrives before the real Git decoration work is released. The
active-decoration benchmark reports listing latency alongside the
decorations-off comparison. On this run, the active request's p95 was 1.419 ms
versus 0.303 ms without active work. The timing is comparison evidence for this
machine, while event ordering is the portable non-blocking gate.

The sorted scenario remains snapshot-bound and therefore costs a full walk. The
absolute timings are not cross-machine thresholds. Repeat the command with the
same machine, filesystem, toolchain, entry count, and page size when comparing
future revisions.
