# CORE-021 Pipeline Paging Allocation Comparison

This comparison measures the public scan command and event contracts before
and after the shared row-filter change. Both runs generated 10,000 empty `.dat`
files, used a 256-entry page, three warmups, and 20 timed samples.

## Machine Profile

- OS: Linux 6.12.101+deb13-amd64, x86_64
- CPU: Intel Core i7-11800H, 16 logical CPUs
- Rust: rustc 1.97.1 (LLVM 22.1.6)
- Cargo: 1.97.1
- Filesystem: Btrfs on NVMe, compression zstd level 1
- Fixture: generated 10,000 empty files in an isolated Git worktree
- Command: `FILER_BENCH_FIXTURE_ROOT=target/bench-fixtures cargo bench -q -p filer-core --bench large_directory`
- Before revision: `31729ec`
- After revision: `d8f08c6`

Fixture creation was excluded from every sample. Allocation columns report the
sample median from the benchmark's `stats_alloc` region. Timing columns report
minimum, median, p95, maximum, and mean elapsed milliseconds.

## Allocation Change

The filtered streaming first page reduced allocation operations by 257, or
8.6%, and allocated bytes by 88,280, or 14.9%. The sorted walked first page
reduced allocation operations by 9,998, or 1.9%, and allocated bytes by
3,439,744, or 9.4%. The fast first and next page rows record the public
continuation timings used by the large-directory contract.
